`okf index` writes an `index.md` for every directory in a bundle that holds
indexable content. Generation is deterministic and offline — identical tree,
byte-identical output, no network and no model call — so running it twice
changes nothing and running it on another machine changes nothing
either.[^prd]

Generated index files are **outputs**. They preserve nothing hand-written,
and drift between what is on disk and what the generator would emit is a lint
concern rather than something the generator negotiates.

# The marker

Every generated file carries an HTML comment on its own line:

```markdown
<!-- generated by okf -->
```

First line everywhere, except on the bundle-root index where it follows the
frontmatter. **Only a marked file can drift**; an unmarked one is a foreign
artifact okf-net reports on but never blames.[^decisions]

The alternatives were all worse. Frontmatter is out because §8 permits it
only on the bundle-root index and only for `okf_version`. A sidecar manifest
is out because a bundle must stay complete as plain markdown, and a manifest
is one more file to lose. Content hashing is out because deleting the marker
is precisely how a consumer *opts out* — that is a feature, not an evasion.

**The position is part of the signal.** Detection reads the marker only where
the renderer writes it: the first non-blank line, after a frontmatter block
if there is one. Scanning the whole file for the string would claim any
hand-written index that merely *quotes* the marker — such as one documenting
okf — and claiming it has teeth, because that index would then be reported as
drift and overwritten as an "update" rather than as the replacement of
hand-written content it actually is. Reading stays tolerant otherwise: CRLF
endings, trailing whitespace, leading blank lines, and an edited root
frontmatter block all still read as marked.

# Ordering

Entries are grouped into `#` sections, one per concept `type`, with a missing
or falsy type landing under `Other`. Concept sections come **first**, ordered
case-insensitively then ordinally by heading text; the `Subdirectories`
section is always **last**, so navigation follows content whatever the
bundle's type vocabulary happens to sort like.

Within a section, entries are ordered **by link — that is, by filename** —
not by title. Every entry has a filename, and a directory cannot hold two
files with the same name, whereas `title` is optional and may repeat, so
ordering by title is neither total nor stable. An ordinal tiebreak keeps the
order total when two names differ only in case.

# The five states

Per directory, the on-disk `index.md` is compared byte-for-byte with the
generated text:

| State | Meaning |
| --- | --- |
| created | no file on disk |
| unchanged | identical |
| drifted | marked, and differs |
| foreign | unmarked, and differs |
| orphaned | marked, but the directory has nothing left to index |

**Drift is `drifted` plus `orphaned`**, and only drift fails
`okf index --check`. Two consequences are worth stating plainly: a *missing*
index is not drift, because nothing on disk can carry a marker and okf-net
cannot claim it wrote a file that is not there; and a *foreign* index is not
drift, per [foreign-bundle
tolerance](../format/foreign-bundle-tolerance.md). The missing case is caught
indirectly almost always — a new directory is a new entry in its parent's
index, and that parent is marked — leaving a deleted bundle-root index as the
one genuine blind spot.

Orphans are **reported, never deleted**. Removing a file a human may still
want is not a generator's call.

A plain `okf index` run *will* overwrite a foreign index — the user asked by
naming the path — but it says so, reporting `replaced (was hand-written)` per
file and a distinct summary count, so the destructive case is never folded
silently into "updated".

# Two surfaces, one computation

`OKF0306` is the lint surface of the same drift computation, and `okf lint`
gets it for free: the linter already caches each file's text and parsed
frontmatter from its own walk and hands both to the generator, so surfacing
drift costs one in-memory render per directory and no extra file read or YAML
parse. It is skipped entirely when configured to hidden.

**`--check` does not consult severity.** Its exit code is fixed at 1 on
drift, because that is the mechanical gate a hook or a CI job branches on.
Promoting or demoting `OKF0306` changes what `okf lint` reports and never
what `--check` returns. See [the lint severity
model](lint-severity-model.md).
